# Markumo — 提交给编程 AI 的初始化资料包

## 使用方法

1. 在电脑上新建空的 Git 仓库/项目目录 `Markumo`，将本包**所有内容解压到仓库根目录**。必须保持 `开发代理规则.md`、`docs/产品需求文档.md`、`docs/界面交互原型.html` 与 `docs/阶段进度与验收台账.md` 的相对路径。
2. 用 Codex、Claude Code 或其他编程 AI 打开 **Markumo 项目根目录**（有本地文件读写能力的编程代理）。开发规则文件已采用中文名；新会话请显式告诉 AI 先读 `开发代理规则.md`，不要依赖工具按约定英文文件名自动发现规则。
3. 第一轮只让 AI 读取文档与规划，不写代码。审核其理解和 Phase 划分后，第二轮再授权执行 Phase 1。
4. Phase 1 完成后，检查实际 UI、运行测试、查看 git diff；满意则自己提交代码，再要求 Phase 2。以此类推，直到 Phase 8。
5. 浏览器打开 `docs/界面交互原型.html` 可以观察目标 UI，但该 HTML 原型不等于已实现的桌面程序。

## 首轮消息（不写代码）

你是 Markumo 的开发负责人。先阅读 开发代理规则.md、docs/产品需求文档.md、docs/阶段进度与验收台账.md、docs/界面交互原型.html，并检查真实仓库。只输出架构理解、需求追踪表、8 个 Phase 的验收点、Phase 1 施工计划与风险，不创建应用代码、不安装依赖、不进入 Phase 2。文档有冲突则说明。收到我明确批准后才能开始编码。

## 授权执行 Phase 1 时的消息

现在只执行 docs/产品需求文档.md 的 Phase 1。严格遵循 开发代理规则.md；先检查仓库 git status 和实际目录，列出具体步骤，然后直接实施并完成本阶段可运行的 Tauri 2 + Rust + Vue 3 + TypeScript + Vite UI 骨架。参考 docs/界面交互原型.html 的整体布局但不要复制其中模拟编辑器作为正式编辑器。所有未开发功能禁用或明确标记，不造假。完成后运行所有环境允许的测试、更新 docs/阶段进度与验收台账.md，展示改动路径、验证结果、人工验收步骤及限制。不得执行 Phase 2，不得自行提交或推送。

## Phase 2–8 模板

现在只执行 docs/产品需求文档.md 中的 Phase N。先读取 开发代理规则.md 与 docs/阶段进度与验收台账.md，检查当前仓库代码和上阶段验收；只做本阶段所需改动，不重建已稳定功能。完成后运行对应测试、更新进度表、列出 git diff 与可复现的手工验收步骤。发现前置条件不满足先说明并修复必要阻塞。不得继续下一个 Phase，不得自行提交或推送。

## 验收消息（每次开发后）

请先不要继续开发。针对当前 Phase 审查真实 git diff，逐条对照 docs/产品需求文档.md 的验收要求，核对功能是否真接上 CodeMirror 6 / Rust / Tauri 而非 Mock；运行可用的测试并报告 PASS、FAIL、NOT RUN 与证据。把阻塞缺陷按严重程度排序，若有未通过项仅修复当前 Phase 范围内的问题，直到满足验收后再停下。
