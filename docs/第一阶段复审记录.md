## 可复现测试与手工验收

前端：`pnpm install --frozen-lockfile` 后运行 `pnpm typecheck`、`pnpm build`、`pnpm dev`。本轮安装更新由 pnpm 执行且锁文件同步；新增依赖仅官方 Tauri CLI，属于本地开发工具，不进入前端运行包。其原生可执行包增加开发依赖下载量，不能将其视为无体积/供应链成本。

UI 回归需要 Node >=20、Playwright 与浏览器。脚本可直接使用本机已经安装的 Playwright，或用 `LIGHTEDIT_PLAYWRIGHT_PACKAGE` 指向其 package.json，不必增加生产依赖。当前环境执行如下（Vite dev/preview 要先启动）：

```powershell
$env:LIGHTEDIT_PLAYWRIGHT_PACKAGE = 'C:/Users/18089/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/package.json'
$env:LIGHTEDIT_TEST_BROWSER = 'msedge'
$env:LIGHTEDIT_TEST_URL = 'http://127.0.0.1:1421' # 开发服务使用 1420
& 'C:/Users/18089/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe' tests/phase1-ui.mjs
```

`test-results/phase1/results.json` 与 PNG 为本机生成证据（已被 gitignore 排除）。脚本没有向外部站点发送文件正文。环境无 Playwright 时需要单独准备测试工具；默认 Node 18.20.2 无法运行当前捆绑 Playwright，因此使用已有 Node 24。

人工复现步骤：

1. 默认打开 main.rs 只读示例；点击 README.md 后才显示禁用的 Markdown 工具条，切回 JSON/Rust 隐藏；源码不变。
2. 点击或用 Enter 折叠 src、editor；打开 today.txt；双击 README 标签固定；关闭并从树重新打开。
3. Ctrl+P，用上下键再过滤 today，Enter 打开；不存在的查询保持空结果；Ctrl+Shift+P 执行布局命令，Esc 退出。
4. 打开设置，检查焦点自动进入、Tab/Shift+Tab 循环、Esc 回到入口；弹窗内 Ctrl+N/Ctrl+P 不触发背后的布局；修改主题、字号和软换行，均只影响当前内存 UI。
5. 工作区拖拽侧栏至 190/420；拖拽时 Ctrl+B 卸载，鼠标后续移动不残留 cursor/监听器；切换单文件布局和专注模式（Esc 退出）。
6. 深浅主题分别在 1200、960、800、680 CSS px 检查，特别检查标题栏操作仍可访问、侧栏/大纲自动收起、编辑区可滚动；关闭全部标签后新建示例标签。
7. 准备 Rust stable、MSVC C++/Windows SDK 后运行 `cargo check`、`cargo test` 和 `pnpm tauri dev`，验证原生标题栏拖拽、最小化/最大化/关闭、WebView CSP/IPC、真实 125%/150% DPI。此步本轮未执行成功。

## 遗留风险与完成门槛

- **阻塞**：Rust 编译、桌面启动、原生窗口及 WebView 行为均未验。工具链就绪后必须先补验 Phase 1；不得基于浏览器成功自动推进。
- **Git**：无法审查用户要求的历史 diff，也无法用 Git 证明没有历史回归；当前结论来自实际源码、明确修复记录与浏览器测试。需要真实 Git 仓库/基线后另行比较，未自行初始化或提交。
- **测试覆盖**：组合输入测试只派发 `isComposing` 事件，不是原生中文 IME 验收；CSS viewport 是缩放等效布局，不是真实 Windows DPI。没有 macOS/Linux、实际 Rust IPC、读写权限、外部冲突、BOM/EOL 等验收。
- **阶段边界**：当前文档模型是有限示例库，不包含真实 EditorState/撤销/滚动保留、唯一 URI/磁盘版本。预览标签只有展示和 pin，完整替换语义留给 Phase 2。不要沿用示例 `content/original` 响应式结构作为后续每次输入的数据流。
- **安全**：dirty 关闭分支只是壳内防御，当前只读示例不会产生 dirty；真实编辑/退出窗口保护必须在接入内核和文件后端时按 PRD 建立。尚未实现任何文件 I/O，不存在本阶段静默覆盖文件的动作，也不等于已经实现安全保存。
- **性能**：仅核查并回归壳的清理/生命周期；没有长期内存测试、启动时间或大文件基准，不作性能保证。

最终状态仍为 Phase 1 REVIEW。未获下一阶段授权，停留在本阶段。
