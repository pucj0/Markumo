# 语法高亮与彩虹括号

设置 → 外观保留原来的“柔和 / 标准 / 鲜明”三档语法高亮。代码底色、行号、选区和光标沿用原来的界面主题，移除了配色卡片和预览。已经保存的 Fleet 值归一为柔和，Monokai 值归一为鲜明，One Dark / GitHub 值归一为标准；前端和 Rust 后端都支持这些历史值。

## 开发版高亮消失

多个 Vite 服务共用依赖预编译缓存时，回归脚本不同的 optimizeDeps 设置会覆盖桌面开发版正在使用的模块，语言扩展可能混用不同的 CodeMirror 实例，最终回退成纯文本。此问题在正在运行的开发服务上复现过：新建文件并切换 JavaScript 后没有任何语法高亮 span，而正式构建正常。

vite.config.ts 现在按服务端口隔离缓存，使用 node_modules/.vite-server-<port>。回归服务重新生成依赖不会影响桌面开发服务。语言加载异常在开发控制台保留原始错误，界面继续保留已有的失败提示与重试入口。

## 所有已注册语言的彩虹括号

原生语法树继续提供结构化层级。没有括号节点的解析器与纯文本使用同一个有界扫描，不按语言白名单过滤。当前 48 个语言选项及其 Markdown 代码围栏均有覆盖，未知语言使用纯文本策略。支持圆括号、方括号与花括号；字符串、注释、正则仍按解析器标记跳过，JSX 正文不作为 JavaScript 表达式处理。

嵌入语法与 Markdown 围栏各自维护配对栈，不跨围栏拼出括号对。扫描保留字符、节点、标记和深度预算，超长的词法作用域按局部窗口着色，避免同步扫描整个文件。二进制、ClassFile 只读查看器及媒体查看器保持原有行为。

彩虹颜色作用到实际字形，覆盖嵌套的语法标点颜色；按嵌套层级使用金、蓝、紫、绿、橙、青、粉、黄绿八色循环，同一对括号保持同色，不随“柔和 / 标准 / 鲜明”降低饱和度。深色主题使用明亮色，浅色主题使用更深的颜色以保证辨识度。当前匹配提示增加下划线，保留层级颜色。错误配对保留错误色与波浪线。

## 验证

- node scripts/brackets-regression.mjs：48 个语言选项与所有围栏、实际字色、普通异步打开、配对作用域、编辑与撤销、性能预算。
- node scripts/syntax-regression.mjs：原有三档高亮、深浅主题、语义颜色、设置与静态导出。
- node scripts/highlight-runtime-regression.mjs：通过真实应用界面切换语言，验证并行 Vite 服务缓存隔离后高亮仍然有效。已纳入 smoke / regression 测试集。
- cargo test --locked --manifest-path src-tauri/Cargo.toml：设置读取、历史配色归一化与持久化。
