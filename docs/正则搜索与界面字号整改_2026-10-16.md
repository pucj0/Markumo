# 正则搜索、搜索栏与全局界面字号整改

日期：2026-10-16。范围为既有 Phase 5/6 专项增量，保持 Rust/Tauri/Vue/TypeScript/CodeMirror/ProseMirror；不推进通用 Phase 7/8。实现与专项自动检查完成，状态 **REVIEW**，不将缺少人工证据的项目标记 DONE。未新增依赖、提交、推送或发布。

## 实际原因及复现

1. 原 CodeMirror 正则引擎可以正确执行 `(import)(\d+)`，匹配 `import123` 和 `import2Something` 中的 `import2`。它不会匹配 `import Vue`；后者应使用 `import\s+(\w+)`。关闭正则时，上述内容作为字面字符串查找，零匹配属于正常结果。
2. 实际交互缺陷：查找已有匹配选区时按 Ctrl+R，应用先将焦点移回编辑器，再调用 CodeMirror `openSearchPanel`；该 API 会从选区重建查询，将捕获组表达式替换成 `import123` 等选中文本，造成匹配数/捕获组替换改变。现在已打开的面板直接切换替换行；重新打开也保留已有查询和选项。
3. Live 原正则缺少 `m` 标志，多行 `^`/`$` 与 CodeMirror 不一致；零宽匹配原本直接跳过。现在使用相同的 `gmu`/`gmiu` 标志，并按 Unicode 码点推进零宽匹配；Live/内嵌代码块使用零宽标记，批量插入通过共享历史撤销。
4. 内嵌代码块原先只设置 CodeMirror SearchQuery，但 CodeMirror 默认高亮插件要求它自己的搜索面板已经打开，因此 Live 的代码块实际没有高亮。现在将 PM 搜索结果直接投影到 CM Decoration，包含当前匹配；延迟到当前 CM 更新结束后派发，避免重入。
5. 原两个搜索栏各自使用 Flex 行和 27px 左侧补白，字号 11–12px。统一 Grid 后还发现 CodeMirror 默认绝对定位关闭按钮及控件 margin 会覆盖自定义布局；现已在面板范围内覆盖，真实几何测试检查输入框边缘、控件交叠和溢出。

## 最终实现及边界

- `SearchBar.ts` 生成共用的输入框、复选选项、SVG 按钮、计数、错误区域和 Grid 结构；两个适配器分别保留正式 CodeMirror SearchQuery 与 PM 搜索事务。正常宽度两行，窄 Pane 按容器宽度重排尾部控件；两个输入框始终共用同一列，没有左侧补白对齐技巧。
- UI 默认 14px、输入框/按钮默认 32px、SVG 16px；字号增大时控制高度增长，图标最多 18px。选项具备真实 checkbox 状态、主题强调背景、标题和无障碍标签；所有按钮支持焦点、悬停和禁用状态。
- Ctrl+F、Ctrl+R、Enter、Shift+Enter、Esc、F3、Shift+F3 覆盖普通文件、Source、Split 源码、Live 和内嵌代码块；Live 搜索不切换模式。搜索输入组合期间不提交中间草稿，不消费组合态 Enter/Esc。
- 共同支持普通字面查找、大小写、全词、Unicode/多行正则，错误显示具体 JavaScript 语法信息。替换依据原始匹配对象展开 `$1`、`$2`、`$&`、`$$`，同时处理命名组及上下文替换。不会对匹配子串再执行一次正则；批量替换从后向前处理 PM 范围，CM 使用单次 ChangeSet。
- Live 搜索对象为可见文本块；Markdown 标记、图片/公式原子节点、不同表格单元格之间不拼接成一个匹配。源码侧搜索原始文本，这一模式边界保留；不能把 Live 宣称为对任意磁盘源码全文搜索。上下文替换的上下文为对应文本块。
- Live 保留 1500 处显示预算；达到上限时拒绝“全部替换”并提示缩小范围，避免静默只替换部分结果。普通文件继续使用 CM 的文档搜索能力。

## 设置与迁移

- 新增 `EditorSettings.uiFontSize`，默认 14，允许 12–20 的整数。设置 → 外观可直接输入，提供恢复默认值；非法输入显示错误并保留上次有效值。
- 设置版本升至 5；旧文件缺少 UI 字号时填入 14，保留原主题、源码字号、Markdown 排版、快捷键和自动保存选择。自动保存的来源判断仍以版本 4 为界，避免升级 UI 设置时重复触发旧迁移提示。
- Rust 同步新增默认、验证、持久化字段和重启测试；保存仍使用既有安全设置服务。
- 根文档应用 `--ui-font-size`，其余大小/行高/控件/图标 Token 派生；菜单、侧栏、目录树、标签、命令面板、设置、对话框、提示、状态栏与 Markdown 工具使用 UI Token。没有全局 `!important` 字号覆盖。
- `fontSize` 与 `markdownTypography.fontSize` 保持独立。浏览器/原生实测 UI 16px 时，源码仍 17px、正文仍 19px；重启后独立配置仍保留。上述 17/19 是测试专用旧设置，不改变产品默认值。
- 目录树实际行高与虚拟列表偏移共用 `uiFontSize + 14`，避免只改 CSS 字体导致滚动错位。

## 人工验收及剩余风险

1. 分别打开 TXT、JS、Java 和 Markdown 三种视图，使用样例 `(import)(\d+)`，确认只匹配数字 import；换成 `import\s+(\w+)` 匹配 `import Vue`。正则关闭后按字面搜索；输入 `[` 再开启正则，应显示具体错误。
2. 查找数字 import 后反复 Ctrl+F/Ctrl+R，原表达式保持；用 `$1-$2` 替换和全部替换，撤销/重做后正文及文件字节符合预期。Live 代码块高亮随正文搜索同步，F3 前后跳转不切 Source。
3. 设置外观 UI 字号为 16/20，检查菜单、目录树、标签、搜索、设置与状态栏；源码及 Markdown 正文字号不变。关闭重启后设置保留，恢复默认只恢复 UI 至 14。
4. Windows 分别采用真实 100%/125%/150% 显示缩放，检查两主题、多 Pane 与设置滚动；使用实际中文输入法测试组合中的 Enter/Esc。自动测试只完成 DPR 仿真和当前 100% 原生窗口，仍需这些人工证据。
5. 极窄 Pane 会增加搜索控制行数来保留输入框宽度；复杂跨节点 Markdown 搜索、任意灾难性回溯正则的耗时隔离、超大文件完整匹配计数不宣称全面解决。既有 Phase 7/8、跨平台和长时运行验收缺项仍保留。
