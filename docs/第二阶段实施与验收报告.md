## 实施与架构取舍

- `DocumentManager` 使用普通 TS 对象及 Map 管理 `EditorState`、原始 `Text` 基线、语言/主题/换行 Compartment、滚动位置与加载代次；Vue 仅订阅可序列化的元数据。输入直接走 CodeMirror Transaction，没有每次输入 IPC，没有全文响应式 `v-model`。
- 整个 pane 只有一个 `EditorView`，切换标签用缓存的 `EditorState`；不通过销毁并重建 EditorView 保存编辑。光标、多选区、历史和折叠在 State 中；滚动在切换前记录，使用 requestMeasure 恢复。
- `TabGroup` 与文档状态分离，最多一个未固定预览槽；替换只释放未编辑的预览文档，首次编辑自动 pin，已有固定标签不降级。明确关闭后释放 state/延后效果；内存样例可以重新打开，未命名草稿关闭后从目录移除。
- 语言按扩展名判定，使用动态 import 加载；手选用 Compartment 重配置，保留文本、选区和撤销。异步请求以文档记录身份及代次校验，过期结果/关闭后的结果不会重新写入；失败不阻止编辑，移除语法扩展并提示重试。
- Markdown 在本阶段以 CM6 Markdown **源码**编辑；Live/Split 明确禁用。根据分阶段权威顺序，Live Preview 在 Phase 5 接入；不为了提前符合最终默认模式而伪造排版。非 Markdown 扩展名的文件不会出现 Markdown 工具条，即使手动选择 Markdown 语法。
- 仅一个 pane/一个 UI tab group；TabGroup 的布局模型可扩展，组之间的交互和双 pane 留给 Phase 6。单文件/工作区目前仍是同一内存文档模型的两种布局，目录和 Ctrl+P 明确为样例库，不冒充真实工作区索引。
- 关闭脏标签弹出 Vue 对话框，默认“继续编辑”；浏览器离开有 beforeunload 保护；Tauri 用实际 `onCloseRequested` 接线，确认放弃后调用 destroy，capability 仅增加 `core:window:allow-destroy`。此原生分支尚未实机验证，不能宣称窗口保护已通过桌面验收。
- 组合输入从 `compositionStarted` 起保护：组合期间不切换/关闭文档，显示需先完成输入的提示；语言/主题/换行效果排队至组合结束。用户需完成输入后再次执行被拦截的切换；避免在未提交输入时替换 state。

## 人工验收步骤

1. `pnpm install --frozen-lockfile`，`pnpm dev`（依赖已装时可用 `npm run dev`），打开 localhost:1420。
2. 编辑 main.rs；切到 README.md 编辑原始 Markdown，確認 Live/Split 禁用、Source 选中；点击返回代码不出现 Markdown 工具条。
3. 固定 README 后打开 today.txt，保持 txt/md/json/ts/rs 五标签；分别修改，回切 Ctrl+Z/Ctrl+Y，观察文本、dirty 点、选区与历史各自保持。
4. 单击样例产生预览，另开样例仅替换未固定槽；双击或首次编辑固定。关闭 dirty 时“继续编辑”和 Esc 均保留文本，只有“放弃修改并关闭”移除。
5. Ctrl+N 输入多行、中文与 emoji；手选语言，开关换行、主题和字体，确认不改源文/不丢撤销。长文滚到中间后换标签再返回检查滚动。
6. Ctrl+F/Ctrl+H 查询/替换并撤销；TypeScript 试 `(` 自动闭合、Tab 两空格、函数折叠、Ctrl+Space 基础补全。
7. **实机待验**：安装 Rust MSVC 与 C++ Build Tools/SDK 后运行 cargo check/test、`pnpm tauri dev`。用 Windows 中文 IME 连续组合、候选选择、换行、快速切标签/语言/主题，再做十次撤销/重做；确认原生关闭脏窗口能取消，只有显式放弃才关闭，CSP/IPC 无错误。
8. **实机待验**：Windows 125%/150% DPI、窄窗口与原生标题栏操作；macOS/Linux 尚未测试。浏览器 viewport 测试只能代表布局尺寸等效。
