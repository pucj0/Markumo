## 实现与架构

- Rust/Tauri 服务负责原生打开/另存为、文件读写、近期文件及独立布局。只在明确文件操作时传递正文；每次输入仍由 CodeMirror Transaction 处理，正文与 EditorState 不进入 Vue 全局响应式状态。
- 文件对话框、Rust 收到的原生拖拽和程序启动参数产生文件授权 token。保存/重开需要有效 token；近期打开要求路径在后端近期列表中。没有接受任意前端路径的通用读写命令，没有宽泛 filesystem 插件权限。
- 验证绝对路径、规范化目标、父目录变化、普通文件类型、符号链接、硬链接与 Windows ADS。保留选择路径和规范化路径，在访问时重新比较。授权代次不同，迟到的关闭释放不会撤销重开的文件；相同规范化路径在前端合并，dirty 和历史保留。
- 打开严格识别 UTF-8、UTF-8/UTF-16LE/BE BOM。可显式按 UTF-8、UTF-16LE/BE、GB18030、windows-1252 打开/重开。不猜测旧编码，不插入替换字符；编码无法表示源码或往返校验不同则拒绝保存。提供另存为 UTF-8。
- CM 源码规范化为 LF；独立 StateField/持久化 RangeSet 记录原始换行符，跟随插入、删除、多选区及历史反向 effect。存活的 CRLF/LF/CR 与混合换行保持原样，新换行采用原文主要风格；不自动增加末尾换行。仅换行风格改变也算 dirty。BOM 留在元数据，在 Rust 编码时写回。
- 保存包含明确的 CM 文本快照与磁盘版本。完成后只把该快照设为基线；期间新编辑仍 dirty，保存不重建 EditorState、不丢历史。取消对话框、权限、占用、编码或冲突失败均保留编辑内容。保存中禁止关闭。
- 磁盘版本包含 SHA-256、字节数和修改时间。写入同目录临时文件、复制基础权限、sync_all，再次检查路径和版本，再替换。Windows 使用 ReplaceFileW 保留 ACL，错误时保留可能的原文件备份并报告路径；新文件使用不覆盖既有目标的 MoveFileExW。Windows 持有拒绝普通写共享的读句柄；Unix 使用 rename 或不覆盖的 hard_link，并同步目录。
- 关闭 dirty 标签/窗口支持继续编辑、放弃、保存并关闭。保存取消/失败或期间出现新修改时不关闭。Rust CloseRequested 保守阻止默认关闭，前端完成确认后才 destroy；关闭监听失败时保留窗口并提示。浏览器保留 beforeunload 保护。
- 最近 20 个文件和独立布局存储于应用数据目录的 `files.json`。只存路径、文件名与布局，不存正文；配置失败单独提示，不把已保存正文误判为未写入。程序再次启动通过 single-instance 接收参数；初次参数和拖拽进入待处理队列，前端先注册事件、再读取队列。
- 普通启动为空白单文件草稿，不创建工作区。顶部提供打开/保存，Ctrl+O/S/Shift+S 和命令面板接线；浏览器磁盘操作禁用并说明原因。既有样例仅在浏览器 `?demo=1` 显式展示。目录树、全文搜索、Markdown Live/Split 仍明确标识后续阶段。

1. 安装用户选定的 Rust MSVC、C++ Build Tools/Windows SDK；重开终端，运行 cargo check/test，再启动 `pnpm tauri dev`。首次依赖解析后保留 Cargo.lock，执行 cargo fmt/clippy。

3. 新建后取消保存，确认仍 dirty；另存为成功后撤销/重做，确认 dirty 基线正确；保存期间继续输入，确认新输入未清理。
4. 外部编辑同一文件，再保存，确认拒绝覆盖、磁盘外部版本不变；另存为已有文件需原生覆盖确认，确认后若再发生变化也应拒绝。
5. 用测试副本检查 readonly、拒绝读/写 ACL、文件独占占用、不可写父目录。失败后正文和旧磁盘内容必须保留。检查 ReplaceFile 备份错误路径和恢复。
6. 多个 dirty 标签关闭/退出：继续编辑、取消文件选择、保存失败、期间新修改均不得关闭。确认监听异常/加载期关闭的 Rust 保守阻止行为。

## 已知风险与取舍

- Rust **未编译**：可能有类型/API、依赖链接或平台实现问题；核心桌面条款无法验收。本阶段不标 DONE，不建议把当前构建用于唯一副本的文件编辑。
- 哈希校验与替换之间仍存在很小的跨进程重命名/路径替换竞态；Windows 读共享锁阻止普通写入，但允许原子 rename，Unix 没有跨进程互斥。不能宣称防御恶意并发路径替换或所有文件系统原子性。后续需 native stress/故障注入及基于句柄身份的进一步审计，优先补本阶段安全验证。
- Windows ReplaceFile 异常可能留下原文件备份，报告会包含恢复路径；未实测故障恢复。Unix 的基础权限复制未覆盖 ACL/xattr/属主完整保留，跨平台不能据此验收。
- 本阶段明确拒绝超限文件：磁盘 bytes 和解码后 UTF-8 文本各 ≤16 MiB、≤200,001 行；每批 ≤20 个、文本总量最多约 64 MiB，待处理队列 ≤100 个。文件符号链接/硬链接拒绝，父目录链接在授权目标一致时允许。大量已打开文档/超大粘贴仍需 Phase 7 性能验证；未实现 streaming 与监控。
- 插入/粘贴的新换行采用原文主风格；原始存活分隔符和撤销保留准确。编码重开要求先保存且会重建该文档的光标/历史，普通标签切换与保存保留历史。BOM/EOL 手动转换 UI 尚无需求接线，仅提供 UTF-8 另存为。
- UTF-16 无 BOM 需显式指定；其他旧编码暂不支持。近期失效路径不自动删除，打开会明确报错。冲突不提供强制覆盖，使用另存为，或先保存副本再关闭/重开。
- 会话/崩溃恢复、外部修改监听属 Phase 7；当前正文不持久化为草稿恢复数据。Browser beforeunload 和合成 composition 不能证明 OS 原生 IME。
